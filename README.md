# Cropwise Operations Automation Suite

Набір консольних Python-інструментів для автоматизації обліку в [Cropwise Operations](https://www.cropwise.com/operations) через REST API v3: імпорт
сільгоспробіт, облік пального, списання ТМЦ зі складу та довідник видів робіт.

Самостійний проєкт, створений на основі роботи з Cropwise Operations API. Не пов'язаний з жодною організацією; усі дані в прикладах вигадані.

Проєкт вирішує реальну задачу: ручне рознесення щомісячних облікових листів, актів списання та
довідників у Cropwise раніше займало години роботи. Скрипти скорочують це до хвилин автоматичної
обробки, включно з валідацією даних, перевіркою дублікатів і обробкою помилок сервера.

## Склад набору

| Скрипт                | Призначення                                                                                                                                                                                              |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `agro1mash_9_0.py`    | **Флагманський скрипт.** Чотири режими в одному інтерактивному меню: (1) імпорт робіт техніки з Excel-облікових листів → `MachineTask`/`AgroOperation`, (2) оновлення пального за логом, (3) автоматичне списання пального зі складу, (4) РЕМОНТ — синхронізація Excel і старого логу при відновленні після обриву чи ручних правок площі. |
| `cropwise_act.py`     | Списання ТМЦ (добрив/ЗЗР/насіння) на конкретне поле — з Excel **або** з Word-акту (`.docx`). Номенклатура і поля тягнуться напряму з сервера (залишки по всіх складах ферми, а не глобальний каталог Cropwise), з локальним фолбеком якщо сервер недоступний. |
| `delete_mash_agro.py` | Масове видалення завдань техніки та агроопераций (за файлом логу або за списком/діапазоном ID) — для відкату тестових/помилкових даних.                                                                  |
| `delete_tests.py`     | Швидка зачистка тестових складських документів за діапазоном ID.                                                                                                                                         |
| `oborotka_tmc_3_1.py` | Імпорт оборотно-сальдової відомості ТМЦ у складський документ надходження (`goods_receipt`), з локальним кешем зіставлення назв товарів.                                                                 |
| `work_type.py`        | Пакетне завантаження довідника видів робіт (КБС-коди) у Cropwise з Excel-файлу, з інтерактивним вибором групи для кожного запису.                                                                        |

Усі скрипти (крім самодостатнього `agro1mash_9_0.py`) використовують спільний модуль `cropwise_common.py` — токен, заголовки запиту, обгортку з retry-логікою.

## На черзі

- **Режим 5 (масовий імпорт)** — розбір одного зведеного місячного Excel-файлу з обліковими
листами кількох водіїв одразу: автоматичне визначення меж блоку кожного водія, витягування
ПІБ/техніки з фіксованих комірок, і подальша обробка кожного блоку через уже наявний пайплайн
Режиму 1. Обов'язкова вимога — попередній "сухий" звіт (список водіїв/технік і як вони
зматчились з довідниками) без жодного звернення до сервера, перед реальною відправкою.

## Можливості (наскрізні для всього набору)

- **Живий пошук у консолі** — вибір водія, техніки, типу роботи (443+ підтипів) чи поля не
вимагає гортання довгого списку: вводиш номер або частину назви, список звужується і
перенумеровується на льоту.
- Стійкий пошук записів у лозі (`find_log_entry_for_row`) — переживає зміну формату ключа між
версіями скрипта і задвоєні записи від Режиму РЕМОНТ, завжди знаходить запис із реальним
`machine_task_id`, а не порожню заглушку.
- Fuzzy-пошук назв (поля/товари/роботи) з толерантністю до відмінностей у форматуванні.
- Перевірка дублікатів на сервері перед створенням нових записів — за датою, водієм, машиною,
полем **і** назвою операції, щоб дві різні роботи в один день на одному полі не сприймались як
дублікат одна одної.
- Обробка нестандартних Excel-даних: діапазони дат в одній комірці, час, що переходить через
північ, "брудні" числові формати.
- Стійкість до мережевих збоїв: автоматичні повторні спроби при HTTP 429 (rate limit) і таймаутах,
запобіжник на кількість сторінок пагінації (щоб несподівано величезний ендпоінт не підвісив
скрипт на години).
- Таймери тривалості в кожному фінальному звіті — скільки часу зайняв конкретний запуск режиму,
і скільки загалом минуло за сесію.
- Локальне кешування довідників (`ref_*.json`, `mapping_cache.txt`) для швидшого повторного запуску.

pip install -r requirements.txt

## Налаштування токена Cropwise

Токен **ніколи** не зберігається в коді жодного зі скриптів. Оберіть один зі способів:

**Варіант 1 — змінна середовища:**

```
export CROPWISE_TOKEN="ваш_токен"   # Windows: set CROPWISE_TOKEN=ваш_токен
```

**Варіант 2 — файл конфігурації.** Створіть `config.json` поруч зі скриптами:

```
{
  "cropwise_token": "ваш_токен"
}
```

(Цей файл уже додано в `.gitignore` — випадково закомітити токен не вийде.) Усі скрипти набору
шукають його в одному й тому самому місці — достатньо створити один раз.

Отримати токен: особистий кабінет Cropwise → Налаштування → API.

## Використання

```
python agro1mash_9_0.py        # флагманський: імпорт робіт + пальне + списання + ремонт
python cropwise_act.py         # списання ТМЦ на поле (Excel/Word)
python delete_mash_agro.py     # відкат тестових даних
python delete_tests.py         # зачистка тестових складських документів
python oborotka_tmc_3_1.py     # імпорт оборотки ТМЦ
python work_type.py            # завантаження довідника КБС
```

Шлях до Excel/Word-файлу можна вводити перетягуванням файлу в консоль — зайві лапки та символи
очищуються автоматично.

## ⚠️ Перед використанням з власним акаунтом Cropwise

У коді є значення, специфічні для акаунту, у якому розроблявся скрипт, — їх треба змінити під
себе (позначені коментарем `⚠️` у коді):

- `DEFAULT_WAREHOUSE_ID` (`agro1mash_9_0.py`) — ID вашого складу
- `DEFAULT_FUEL_WH_ITEM_ID` (`agro1mash_9_0.py`) — ID позиції "Пальне" у вашому довіднику товарів
- ID складу/контрагента в `oborotka_tmc_3_1.py` (запитується інтерактивно або має дефолтне
значення `13` — перевірте під свій акаунт). `cropwise_act.py` тепер сам визначає список складів
через `/api/v3/warehouses`, окреме налаштування ID тут не потрібне.

## Мережа / корпоративний проксі

За замовчуванням SSL-сертифікати перевіряються (безпечно). Якщо ваша мережа використовує
проксі з власним сертифікатом і запити не проходять — можна тимчасово вимкнути перевірку змінною
середовища (не хардкодом у коді):

```
export CROPWISE_DISABLE_SSL_VERIFY=1
```

## Обмеження API (важливо)

Деякі речі, які виглядають логічними, **не підтримуються** офіційним Cropwise API v3 (перевірено
емпірично, включно зі зверненням до реального сервера):

- Пряма прив'язка складського документа списання до конкретного `MachineTask` — сервер повертає
`500 Internal Server Error`. Робочий обхід: прив'язка через `AgroOperation`, яка вже пов'язана з
потрібним завданням.
- Масове (bulk) створення об'єктів не задокументоване для `machine_tasks`/`agro_operations`.
- `/api/v3/wh_stocks` без параметра `warehouse_id` поводиться як історичний журнал рухів, а не
поточний залишок — без фільтра по складу запит може повернути десятки тисяч записів і
надовго зависнути.
